# LibraryHub

Веб-приложение для школьной библиотеки: Go + Chi, PostgreSQL + pgx/v5, HTML/CSS и Vanilla JavaScript. Интерфейс и REST API обслуживаются одним Go-сервером.

## Быстрый запуск

Нужны Docker Engine и Docker Compose v2 или новее с доступом к интернету для загрузки образов и Go-модулей.

```sh
docker compose up --build
```

Откройте **http://localhost:8080**. Создавать `.env` для этого запуска не обязательно: Compose содержит значения для локальной разработки. PostgreSQL ожидается через healthcheck; сервер дополнительно повторяет подключение до 60 секунд. Миграции и заполнение выполняются до начала обслуживания HTTP.

Первый запуск добавляет **24 книги, 174 экземпляра, 12 читателей и 26 выдач**: 10 активных (4 просрочены), 16 завершённых. Даты рассчитываются относительно дня первого запуска. Последующие запуски сохраняют данные, не повторяя seed. Изменение `.env` не меняет пароль уже созданного тома PostgreSQL.

Остановка:

```sh
docker compose down
```

Данные находятся в Docker volume `postgres_data` и сохраняются после остановки. `docker compose down -v` полностью удалит библиотеку и при следующем запуске создаст её заново.

Приложение предназначено для **локальной доверенной среды**. Авторизации нет. HTTP-порт привязан к `127.0.0.1`, PostgreSQL по умолчанию не опубликован на хост. Не разворачивайте приложение публично без аутентификации, управления доступом, HTTPS и дополнительных мер защиты.

## Возможности

- Обзор: статистика фонда, доступные экземпляры, активные и просроченные выдачи, последние выдачи, популярные книги, распределение по жанрам и график за шесть месяцев.
- Каталог: создание, карточка, редактирование, удаление; независимый поиск по названию и автору, жанр, доступность, сортировка, серверная пагинация.
- Читатели: CRUD, поиск по ФИО, фильтр по классу, карточка с постраничным списком книг на руках.
- Выдачи: поиск книги и читателя через API, выбор дат, возврат с фактической датой; вкладки активных, просроченных и завершённых выдач.
- Аналитика: наименования и экземпляры, читатели, выдачи за месяц, популярность книг и жанров, графики Chart.js.
- Светлая/тёмная тема с сохранением выбора, мобильное меню, модальные окна, toast-уведомления, skeleton-загрузка, пустые состояния и сообщения об ошибках сети.

Основная логика работает без внешних frontend API. Chart.js 4.4.8, Lucide 0.468.0 и шрифт Inter загружаются из CDN; для их загрузки браузеру нужен интернет. Если Chart.js недоступен, данные отображаются резервными графиками на HTML/CSS. Без шрифта используется системный, без Lucide остаются текстовые кнопки и доступные подписи. Для полностью автономной сети библиотеки можно сохранить локально в `web/vendor`, изменить подключения в `web/index.html` и CSP в `internal/middleware/middleware.go`.

## Локальная разработка

Нужны Go 1.23+ и PostgreSQL 17+ с расширением `pg_trgm` (в Docker-образе PostgreSQL оно доступно). Порт 5432 должен быть свободен.

```sh
cp .env.example .env
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db
go mod tidy
make run
```

Если app уже запущен через Compose, остановите его командой `docker compose stop app`, чтобы освободить 8080. Локальный Go-сервер сам применяет миграции. Frontend не требует npm, сборки или отдельного сервера.

### Конфигурация

Процесс читает `.env`, затем использует окружение с более высоким приоритетом.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HTTP_ADDR` | `:8080` | Адрес HTTP-сервера |
| `DATABASE_URL` | `postgres://libraryhub:libraryhub@localhost:5432/libraryhub?sslmode=disable` | Подключение для локального Go-запуска |
| `DB_TIMEOUT` | `5s` | Максимальное время обработки API, включая SQL |
| `WEB_DIR` | `web` | Каталог frontend; процесс запускается из корня проекта |
| `POSTGRES_USER` | `libraryhub` | Пользователь БД в Compose |
| `POSTGRES_PASSWORD` | `libraryhub` | Пароль БД в Compose |
| `POSTGRES_DB` | `libraryhub` | Имя БД в Compose |

В Compose `DATABASE_URL` приложения автоматически использует хост `db` и переменные `POSTGRES_*`; `HTTP_ADDR` и `WEB_DIR` контейнера фиксированы конфигурацией. В пароле URL-спецсимволы требуют URL-кодирования в строке подключения. `.env` не включён в образ и исключён из Git.

Контейнеры используют `Europe/Moscow`; при самостоятельной установке настройте одинаковые часовые пояса процесса Go и PostgreSQL. Сроки хранятся как `DATE`: книга просрочена, если срок возврата **раньше** текущего дня и возврат ещё не зарегистрирован.

## Архитектура

```text
cmd/server/main.go           конфигурация, подключение, миграции, HTTP, shutdown
internal/config/             .env и переменные окружения
internal/handler/            маршруты Chi, JSON, параметры, HTTP-ошибки
internal/service/            валидация и сценарии изменения данных
internal/repository/         параметризованный SQL и атомарные транзакции
internal/model/              структуры и доменные ошибки
internal/middleware/         заголовки безопасности
migrations/                 встроенные SQL и простой мигратор
web/index.html              оболочка приложения
web/css/style.css           адаптивный интерфейс и темы
web/js/app.js                страницы, формы, взаимодействия, графики
web/js/api.js                Fetch, таймауты и ошибки
web/js/components/ui.js      безопасный вывод, таблицы, уведомления
internal/service/*_test.go   модульные тесты
tests/integration_test.go   тесты бизнес-сценариев на настоящей PostgreSQL
```

Handler разбирает запрос; Service проверяет данные; Repository выполняет SQL. Чтение без дополнительной бизнес-логики идёт из Handler прямо в Repository. Транзакционные правила остаются рядом с SQL, где их можно гарантировать при конкурентных запросах.

### Целостность и транзакции

- Выдача: `SELECT … FOR UPDATE` книги, проверка доступности, блокировка читателя, вставка выдачи и уменьшение остатка в одной транзакции.
- Возврат: блокировка книги, затем выдачи; проверка повторного возврата и даты; увеличение остатка вместе с обновлением выдачи.
- Редактирование фонда: под той же блокировкой пересчитывается остаток; общее количество нельзя уменьшить ниже числа книг на руках. `available_copies` не принимается от клиента.
- Удаление: блокировка книги/читателя, проверка активных выдач, установка `deleted_at`. Запись исчезает из каталога и выбора, но внешние ключи и история остаются целыми. Физического удаления через API нет.
- Снимки названия книги и имени читателя в выдаче сохраняют исторические данные после редактирования. Карточки действующих записей показывают актуальные данные. Удалённая карточка возвращает 404, сама строка истории остаётся доступной.
- `CHECK` не допускает отрицательных остатков или остатка больше фонда; внешние ключи защищают связи. Частичные индексы ускоряют активные выдачи; GIN `pg_trgm` поддерживает поиск через `ILIKE`.
- Значения передаются параметрами `$1…`; сортировка выбирается из белого списка, данные не подставляются в SQL. Пользовательский текст экранируется на frontend, небезопасные HTML-описания не поддерживаются.
- Миграции `001_schema.sql` и `002_seed.sql` встроены в бинарник. Каждая выполняется в транзакции и регистрируется в `schema_migrations`. Advisory lock предотвращает одновременное применение несколькими процессами. Новый SQL-файл с очередным номером применяется при следующем старте. Выполненные файлы не следует менять.

База для аналитики — SQL, в браузере нет демонстрационных записей. «Всего книг» означает число наименований, «Всего экземпляров» — сумму `total_copies`. Распределение по жанрам считает наименования текущего фонда; популярность считает все выдачи, включая возвращённые и исторические записи удалённых книг. История — только завершённые выдачи; без `status` API выдач возвращает все записи.

## REST API

Все ответы API, кроме успешного удаления, — JSON. Ошибка имеет вид `{"error":"Описание"}`. Списки возвращают:

```json
{"items": [], "total": 0, "page": 1, "limit": 10}
```

Общие параметры списков: `page` (от 1), `limit` (1–100, по умолчанию 10), `search`. Поиск регистронезависимый, выполняется SQL-запросами. Символы `%` и `_` имеют стандартный смысл шаблона `ILIKE`.

| Метод | Путь | Дополнительно |
| --- | --- | --- |
| GET | `/api/books` | `search` по названию, `author`, `genre`, `availability=available/unavailable`, `sort=title/author/year`, `order=asc/desc` |
| GET | `/api/books/{id}` | Карточка книги |
| POST / PUT | `/api/books`, `/api/books/{id}` | Создать / изменить книгу |
| DELETE | `/api/books/{id}` | Удалить книгу без активных выдач |
| GET | `/api/readers` | `search` по ФИО, `class` |
| GET | `/api/readers/{id}` | Карточка читателя |
| POST / PUT | `/api/readers`, `/api/readers/{id}` | Создать / изменить читателя |
| DELETE | `/api/readers/{id}` | Удалить читателя без активных выдач |
| GET | `/api/loans` | `status=active/overdue/history`, `reader_id`, `search` по книге или читателю |
| POST | `/api/loans` | Выдать книгу |
| POST | `/api/loans/{id}/return` | Вернуть книгу |
| GET | `/api/stats/overview` | Основные показатели |
| GET | `/api/stats/popular-books` | Топ-5 книг |
| GET | `/api/stats/genres` | Распределение фонда по жанрам |
| GET | `/api/stats/popular-genres` | Популярность жанров по выдачам |
| GET | `/api/stats/loans-by-month` | Шесть месяцев, включая текущий; месяцы без выдач содержат 0 |
| GET | `/api/options/genres`, `/api/options/classes` | Списки значений для фильтров |
| GET | `/api/health` | Проверка HTTP и подключения к БД |

Успех: `200`, создание: `201`, удаление: `204`. Ошибки валидации/JSON: `400`, запись не найдена: `404`, конфликт бизнес-правил: `409`, внутренняя ошибка: `500`. Неизвестные поля JSON отклоняются. Тело ограничено 64 КБ.

Создание книги:

```sh
curl -X POST http://localhost:8080/api/books \
  -H 'Content-Type: application/json' \
  -d '{"title":"Новая книга","author":"Автор","genre":"Наука","year":2024,"isbn":"","description":"Описание","total_copies":3}'
```

Обновление использует тот же набор полей. `id`, `available_copies`, `created_at` сервер вычисляет самостоятельно. ISBN необязателен, описание может быть пустым. Общее число экземпляров: 0–100000; год: от 1 до следующего календарного года.

Читатель:

```json
{"name":"Иван Петров","class":"9А"}
```

Выдача (подставьте актуальные даты; дата выдачи не может быть в будущем):

```json
{"book_id":1,"reader_id":2,"issued_at":"2026-10-26","due_at":"2026-11-09"}
```

Возврат принимает `{"returned_at":"2026-10-26"}` или `{}` для сегодняшней даты. Нельзя вернуть раньше даты выдачи или позже сегодняшнего дня.

## Проверки

```sh
go mod tidy
make test
make build
go vet ./...
node --check web/js/app.js
node --check web/js/api.js
node --check web/js/components/ui.js
docker compose config --quiet
```

Модульные тесты проверяют валидацию, нормализацию, даты и передачу доменных ошибок. Интеграционные тесты в `tests/` используют настоящую PostgreSQL; без `TEST_DATABASE_URL` они **явно пропускаются**.

Для полного набора:

```sh
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db
TEST_DATABASE_URL='postgres://libraryhub:libraryhub@localhost:5432/libraryhub?sslmode=disable' make integration
```

Каждый интеграционный тест создаёт отдельную схему и удаляет её после выполнения. Пользователю БД нужны права `CREATE SCHEMA` и установки `pg_trgm` (либо установите расширение заранее). Используйте отдельную локальную тестовую БД. Проверяются:

1. Выдача доступной книги и уменьшение остатка.
2. Отказ при отсутствии экземпляров без изменения остатка.
3. Возврат и увеличение остатка.
4. Повторный возврат без изменения остатка.
5. Запрет удаления книги и читателя с активной выдачей; сохранение истории после завершения.
6. Десять одновременных запросов на один экземпляр и десять одновременных возвратов: успешна ровно одна операция каждого типа.
7. Повторное применение миграций без дублирования seed.

### Проверено в среде разработки этого проекта

- Модульные Go-тесты Service с `-race`: успешно.
- `go vet` для Service/Model/Middleware, синтаксис трёх JavaScript-модулей, 8 проверок frontend-хелперов, форматирование Go и обе конфигурации Compose: успешно.
- Схема без расширения/GIN-индексов, seed, целостность остатков и запрос графика проверены на PostgreSQL 18 в однопользовательском режиме: 24 книги, 174 экземпляра, 164 доступных, 12 читателей, 26 выдач, 10 активных, 4 просроченных, 0 расхождений остатков.
- Попытки полной сборки и полного набора Go-тестов остановились на зависимостях: sandbox запрещает сетевую загрузку отсутствующих версий Chi/pgx/godotenv. Поэтому `go.sum` не сформирован; при локальном запуске выполните `go mod tidy`. Dockerfile скачивает зависимости во время сборки.
- Docker-запуск не проверен: нет доступа к Docker daemon. PostgreSQL в серверном режиме также не запускается: sandbox запрещает создание сокетов. Интеграционные тесты, HTTP end-to-end и визуальная проверка браузером остаются для окружения с этими возможностями. Локальная PostgreSQL не содержит `pg_trgm`, поэтому полную миграцию с этим расширением в данной среде выполнить нельзя.
